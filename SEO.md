# SEO CODEX-UZB — что сделано и что нужно сделать вручную

## Почему сайта не было в Google

1. **Сайт новый** (первый деплой 05.09.2026) и **нигде не зарегистрирован** — Google о нём просто не знал.
   Проверка `site:codex-uzb.uz` → 0 проиндексированных страниц.
2. **Не было `robots.txt` и `sitemap.xml`** — оба адреса отдавали 404.
3. **Весь текст рисовался JavaScript'ом.** В HTML был пустой `<div id="root">` — робот получал страницу без единого слова о услугах.
4. **Четыре языка жили на одном адресе.** Язык выбирался через `localStorage`/язык браузера,
   у робота их нет → он видел только узбекскую версию. Русских слов («создание сайта»,
   «услуги программиста») в индексируемом HTML не существовало вообще.
5. Не было `canonical`, `hreflang`, микроразметки Schema.org.

## Что уже исправлено в коде

- **Отдельный URL для каждого языка:** `/` (uz), `/ru/`, `/en/`, `/zh/`.
- **Пререндер при сборке** (`npm run build`): в каждом файле лежит готовый HTML со всем текстом
  (~60 КБ вместо пустого div). Робот читает страницу без запуска JS, браузер потом «оживляет» её (hydrate).
- **`robots.txt`** и **`sitemap.xml`** со всеми языковыми версиями и `hreflang`.
- **`canonical`, `hreflang`, `x-default`, Open Graph, Twitter Card** на каждой странице.
- **Микроразметка Schema.org**: `ProfessionalService` (контакты, адрес, часы работы, соцсети,
  каталог услуг), `WebSite`, `FAQPage` (вопросы могут показаться прямо в выдаче Google).
- **Title и description переписаны под запросы**, например RU:
  «Создание сайтов и мобильных приложений в Ташкенте — CODEX-UZB».
- Переключатель языков — обычные ссылки `<a href="/ru/">`, робот по ним переходит.
- `vercel.json`: `trailingSlash: true` + кэш для `/assets/`.

## Что нужно сделать вручную (без этого сайт не появится)

### 1. Задеплоить новую сборку
```bash
cd codex-web && npm run build && vercel --prod   # или git push, если подключён Git
```
Проверить: https://www.codex-uzb.uz/robots.txt и /sitemap.xml должны отдавать 200, а не 404.

### 2. Google Search Console — главное
1. https://search.google.com/search-console → добавить ресурс **Домен** `codex-uzb.uz`
   (подтверждение через TXT-запись в DNS — в Vercel: Settings → Domains → DNS Records).
2. Sitemaps → добавить `sitemap.xml`.
3. Проверка URL → вставить `https://www.codex-uzb.uz/` → **«Запросить индексирование»**.
   Повторить для `/ru/`, `/en/`, `/zh/`.

Первые страницы обычно появляются в поиске через **3–14 дней**.

### 3. Яндекс.Вебмастер
Для Узбекистана и русскоязычных запросов Яндекс даёт заметный трафик:
https://webmaster.yandex.ru → добавить сайт → sitemap → «Переобход страниц».

### 4. Google Business Profile (карточка компании)
https://business.google.com — создать профиль «CODEX-UZB», категория «Разработка программного
обеспечения», Ташкент, телефон, сайт. Это даёт показы по запросам «создание сайта Ташкент»
и попадание в Google Карты. Один из самых быстрых источников первых клиентов.

### 5. Ссылки на сайт (без них позиций не будет)
Google ранжирует сайты, на которые ссылаются другие. Минимум:
- ссылка в шапке Telegram-канала, в Instagram bio, в подписи писем;
- профили: LinkedIn, Clutch, GoodFirms, Behance, GitHub-организация;
- узбекские каталоги: OLX.uz, Golden Pages, uz.b2b, Torg.uz, Uybor (где уместно);
- посты о проектах на vc.ru / Habr / Medium со ссылкой на сайт.

### 6. Ожидания по срокам
- Индексация: 3–14 дней.
- Запросы по бренду («codex-uzb», «codex uzb») — 1–3 недели.
- Конкурентные запросы («создание сайта Ташкент», «разработка сайтов Узбекистан») — **3–6 месяцев**
  и только при регулярном добавлении контента и ссылок. Одностраничник почти никогда не выходит
  в топ по таким запросам — нужны отдельные страницы под каждую услугу (см. ниже).

## Следующий шаг для роста позиций

Сейчас это один лендинг = одна страница = один набор ключевых слов. Чтобы ранжироваться по
десяткам запросов, нужны отдельные страницы под услуги, например:
`/ru/sozdanie-saytov/`, `/ru/razrabotka-mobilnyh-prilozheniy/`, `/ru/internet-magazin/`,
`/ru/telegram-bot/`, `/ru/crm-razrabotka/`, плюс блог/кейсы.

Инфраструктура для этого уже есть: `scripts/prerender.mjs` собирает статические страницы —
достаточно добавить в него список страниц и тексты.

## IndexNow (Bing + Яндекс)

Ключ: `b653176e6279bbb93aad3ab4c11dd260`, файл-подтверждение: `public/b653176e6279bbb93aad3ab4c11dd260.txt` → https://www.codex-uzb.uz/b653176e6279bbb93aad3ab4c11dd260.txt

Уведомить поисковики о новых/изменённых страницах:
```bash
cd codex-web && node scripts/indexnow.mjs
```
Google IndexNow не поддерживает — для него нужен Search Console (см. выше).

## Проверка

```bash
cd codex-web && node scripts/seo-check.mjs
```
Скрипт дёргает живой сайт и проверяет: robots/sitemap, редиректы, для каждой из 4 страниц —
код ответа, title, description, canonical, lang, hreflang, наличие текста в HTML без JS,
язык контента, H1, микроразметку, Open Graph; теги подтверждения прав, ключ IndexNow, скорость.
